## Invariant Rules

These apply to every session without exception:

1. **Always `uv run python`** — never raw `python` or `python3`. The `.venv`
   has CUDA-specific packages; raw python may resolve a different interpreter.

2. **Always use `run_experiments.py`** to launch experiments — never call
   `uv run python experimentsN.py` directly. The runner handles log paths,
   GPU assignment, and the results table.

3. **Throwaway scripts go in `scripts/tmp/`** — never `python -c "..."` inline.
   Write to `scripts/tmp/<name>.py`, then run with
   `uv run python projects/omniglot-ar/scripts/tmp/<name>.py`.

4. **No bash polling loops** — to check progress, read the log file once or
   write a Python script. Never `while true; do ...; sleep N; done`.

5. **Never rsync `results.jsonl` from a laptop to the GPU box.** Experiments
   run on the GPU box, so the box's copy is the only real one; the laptop's is
   usually an empty placeholder. A plain `rsync -az projects/omniglot-ar
   <box>:.../projects/` silently overwrites the box's results with that empty
   file and destroys every run. Always exclude it:

   ```bash
   rsync -az --exclude 'results.jsonl' --exclude '__pycache__' --exclude 'logs/' \
     projects/omniglot-ar <box>:~/Projects/seewhy/projects/
   ```

   Pull the other way (`box → laptop`) to get results for report generation.
   The per-eval log lines carry every field in `history`, so a clobbered
   `results.jsonl` can be reconstructed from `logs/expN.log` — but re-running is
   the safer fix when the runs are cheap.

## Running Experiments

```bash
# Fire and forget — detach to background, return immediately
uv run python projects/omniglot-ar/scripts/run_experiments.py --bg exp1

# With auto-viz after completion
uv run python projects/omniglot-ar/scripts/run_experiments.py --bg --viz scripts/gen_viz_exp1.py exp1

# Sequential blocking (safe — no XLA contention)
uv run python projects/omniglot-ar/scripts/run_experiments.py exp1 exp2

# Parallel across GPUs
uv run python projects/omniglot-ar/scripts/run_experiments.py --parallel exp1 exp2

# Pin to a specific GPU
uv run python projects/omniglot-ar/scripts/run_experiments.py --gpu 1 exp1
```

Logs always go to `projects/omniglot-ar/logs/{exp_name}.log`.

## JAX Performance

### Use `lax.scan` for the batch loop

Replace `for b in range(num_batches)` with `jax.lax.scan`. This eliminates
thousands of Python→XLA dispatch calls per epoch and lets XLA fuse the full
epoch as one computation.

```python
def make_epoch_fn(optimizer):
    def scan_body(carry, inputs):
        params, opt_state = carry
        batch, key = inputs
        (loss, aux), grads = jax.value_and_grad(loss_fn, has_aux=True)(
            params, batch, key
        )
        updates, new_opt_state = optimizer.update(grads, opt_state, params)
        return (optax.apply_updates(params, updates), new_opt_state), (loss, *aux)

    def epoch_fn(params, opt_state, Xs_batched, epoch_key):
        num_batches = Xs_batched.shape[0]
        keys = jax.vmap(lambda b: jax.random.fold_in(epoch_key, b))(
            jnp.arange(num_batches)
        )
        (params, opt_state), stats = jax.lax.scan(
            scan_body, (params, opt_state), (Xs_batched, keys)
        )
        return params, opt_state, *[s.mean() for s in stats]

    return jax.jit(epoch_fn)
```

Pre-batch data before calling:
```python
Xs_batched = Xs[:num_batches * BATCH_SIZE].reshape(num_batches, BATCH_SIZE, -1)
```

### GPU isolation

Never launch two JAX experiments on the same GPU simultaneously. XLA
compilations from two processes compete for memory and can OOM. Use
`run_experiments.py` sequential mode or `--parallel` (which sets
`CUDA_VISIBLE_DEVICES` per process).

### First epoch is slow — JIT compilation

Epoch 0 includes XLA compilation time and may be 10–20× slower than
subsequent epochs. Do not judge speed from epoch 0.

### Don't close over large arrays in `@jax.jit`

If a `@jax.jit` function closes over a large array, JAX embeds it as a
compile-time constant and allocates it on the GPU at compile time. This
silently OOMs when the function is recompiled for a new shape or after
prior allocations have fragmented memory.

```python
# Bad — E_b (~245 MB) captured as constant, OOMs on recompile
@jax.jit
def epoch(W, b, state):
    (W, b), state = jax.lax.scan(step, ((W, b), state), (E_b, Y_b))[0]
    return W, b, state

# Good — pass as arguments
@jax.jit
def epoch(W, b, state, E_b, Y_b):
    (W, b), state = jax.lax.scan(step, ((W, b), state), (E_b, Y_b))[0]
    return W, b, state
```

## Experiment File Structure

Every experiment file follows the same layout:

```
module docstring    — hypothesis, what changed, usage line
hyperparameters     — UPPER_SNAKE_CASE constants at module top
precomputed consts  — JAX arrays that don't change per run
utilities           — n_params, append_result, any project-specific helpers
init_params()
encode() / forward()
loss_fn()
make_epoch_fn()     — returns JIT-compiled epoch fn
eval_metrics()      — @jax.jit accuracy / metric functions
train()             — epoch loop with periodic viz; returns (params, history, elapsed)
__main__            — load data → init → train → visualize → append_result
```

Hyperparameters go at module level in `UPPER_SNAKE_CASE` so they are visible
at a glance and easy to diff between experiments.

## Results Logging

### Skip-if-done

Check at the top of every `__main__` whether the experiment is already in the
output JSONL and exit early. Makes batch runners idempotent after a crash:

```python
done = set()
if JSONL.exists():
    with open(JSONL) as f:
        for line in f:
            try: done.add(json.loads(line).get("experiment"))
            except Exception: pass
if EXP_NAME in done:
    logging.info(f"{EXP_NAME} already done — skipping")
    exit(0)
```

### JSONL deduplication

Two concurrent processes both read the `done` set before either has written,
then both write the same rows. After any crash or concurrent run, deduplicate
by key before analysis:

```python
seen, unique = set(), []
for r in rows:
    k = r.get("experiment")   # or whatever the natural key is
    if k not in seen:
        seen.add(k)
        unique.append(r)
```

### Append one JSON object per experiment to `results.jsonl`:

```python
JSONL = Path(__file__).parent / "results.jsonl"

def append_result(row: dict):
    with open(JSONL, "a") as f:
        f.write(json.dumps(row) + "\n")
```

Every row must include: all hyperparameters, `n_params`, `time_s`, `epochs`,
final metric values, and per-epoch curve lists. Curves are cheap to store and
invaluable for re-plotting without re-running.

## Saving and Reloading Params

Save params at the end of every run:

```python
with open(Path(__file__).parent / f"params_{EXP_NAME}.pkl", "wb") as f:
    pickle.dump({k: np.array(v) for k, v in params.items()}, f)

with open(Path(__file__).parent / f"history_{EXP_NAME}.pkl", "wb") as f:
    pickle.dump(history, f)
```

To reload in a script:

```python
with open("projects/omniglot-ar/params_exp1.pkl", "rb") as f:
    params = {k: jnp.array(v) for k, v in pickle.load(f).items()}
```

Both pkl files are gitignored. `results.jsonl` is the only committed output.

Shared visualization functions live in `lib/viz.py`. Do not inline
visualization code in experiment files — it diverges and is hard to keep

from lib.viz import save_learning_curves, save_reconstruction_grid

url = save_matplotlib_figure("exp1_learning_curves", fig, format="svg")

## Reports

This project uses **Typst**, not markdown. A report is a directory of small
files — `sections/*.typ` hand-written, `figures/*.typ` and `assets/*` generated
— compiled by `typst-py` and pushed to R2. Because every part is a separate
file, updating is partial by nature: rewrite one section, recompile, publish.

Engine: `shared_lib/typst_report.py`. Plots: `shared_lib/typst_plot.py`, which
wraps [gribouille](https://github.com/mcanouil/gribouille) — a grammar of
graphics for Typst. A figure is *data plus a declarative spec*, not imperative
drawing code.

There are **two trees**, sharing the figure code:

| tree | shape | script |
|------|-------|--------|
| `report/` | short-form essay, 5 sections | `publish_report.py` |
| `paper/`  | full paper: abstract, TOC, numbered sections, bibliography | `publish_paper.py` |

`paper/template.typ` exports `paper` (not `report`) as its show-rule function,
which is why `publish_paper.py` passes `template_fn="paper"` to
`preview_section`.

**Only the PDF is uploaded.** The shared link is a ~3 KB HTML page that renders
that PDF client-side with pdf.js from a CDN, so a report does not also cost a
few hundred KB of SVG showing the same content. Pass `--with-svg` if a
script-free rendering is needed somewhere.

### The loop

```bash
uv run python projects/omniglot-ar/scripts/gen_report.py --into paper    # figures from results.jsonl
uv run python projects/omniglot-ar/scripts/publish_paper.py --status     # what moved
uv run python projects/omniglot-ar/scripts/publish_paper.py --preview    # paper/out.pdf, no upload
uv run python projects/omniglot-ar/scripts/publish_paper.py              # compile + push
```

Iterate on one section without compiling the rest or uploading anything:

```bash
uv run python projects/omniglot-ar/scripts/publish_paper.py --section 06-results
```

Always look at a preview before pushing. Rendering to PNG and actually looking
at it catches what reading the source does not — silently-substituted fonts,
`—` escapes surviving into the output, Typst parsing a leading `+` in a
table cell as a list marker.

### Writing a section

Typst evaluates an `#include`d file in its own scope, so **every section must
start with `#import "/template.typ": *`** — it does not inherit from `main.typ`.
That gives you `#fig`, `#callout`, and `#kv`. Paths are root-relative, with
`report/` as the Typst root.

Place a generated figure with:

```typst
#fig(include "/figures/learning_curves.typ", caption: [Accuracy over training.])
```

Adding or reordering sections means editing the `#include` lines in `main.typ` —
that list *is* the report's structure.

### Adding a figure

Write a function in `lib/figures.py` that takes a results row and returns a
`Figure`, then register it in `build_figures()` in `scripts/gen_report.py`.
Nothing in `lib/figures.py` writes to disk; `write_figures()` does that once,
and skips files whose content is unchanged.

Use the high-level helpers (`line_chart`, `bar_chart`, `heatmap`,
`scatter_chart`) where they fit, and drop to the grammar layer (`aes`,
`geom_*`, `scale_*`) for anything else. `g("geom-violin", ...)` reaches any
gribouille function not explicitly wrapped.

Rasterised images (sample grids, attention maps) are the exception — write a
PNG into `report/assets/` and place it with `#image("/assets/x.png")`.
